## Approved design constraints

- `human-spec.md` (H), Specification / overview 1–3: keep repository YAML and the existing public URLs/template structure; split custom/default rendering into two functions, dispatch by filename-derived startup registry, and do not mutate parsed content during requests. No CMS or Partner self-service work.
- H, Formal YAML Schema / note and validation paragraphs: implement a **custom Python validator class** shared by startup and CI. The displayed schema is a reference, not a shipped JSON Schema artifact. Do not add a JSON Schema dependency, meta-schema test, or removed test 10.b. Preserve required fields, types, URI formats, nested constraints, unknown-field rejection and the six-digit hex pattern without inventing extra restrictions.
- H, Differences with current schema: migrate the three publishers, merge `snapcrafters-snaps.yaml` into `snapcrafters.yaml`, rename `publisher` to `display_name`, remove `username`, `developer_validation`, `show_popular_snaps`, `hide_all_snaps`, `link_to_search` and `blog_slug`, and derive layout from whether `listed_snaps` is nonempty.
- H, Security / Publisher account enumeration; `testing-plan.md` (T), 3.c/3.d: successful empty Store snap responses mean HTTP 200 with the applicable empty default/custom page, not proof of account nonexistence. Preserve the explicit `snap-quarantine` 404 exception. T / Mocks item 1 describes fixture metadata, not permission for a publisher lookup endpoint or a new 404 path; use actual Store snap responses and their publisher metadata.
- H, Rationale and Security / Publisher pages content; T / exclusions 1–3, 8 and 13.a: publisher eligibility, forbidden HTML, asset hosting and content accessibility are review-only. Do not add a runtime verified gate, automatic revocation, sanitization, or CI enforcement of those review rules. Store trust status is rendered at request time, never trusted from YAML.
